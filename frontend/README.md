# mailr web client

Gmail-style web client for mailr. React 19 + TypeScript (strict), Vite, TanStack Query and
Virtual, React Router, TipTap, Zustand, lucide icons. No CSS framework: design tokens in
`src/styles/tokens.css` drive light and dark themes and three densities.

## Develop

```bash
npm install
npm run dev              # http://localhost:5173, proxies /api to http://localhost:8025
MAILR_API=http://host:port npm run dev   # point the proxy elsewhere
```

Without a backend, run the mock API (in-memory sample data in the shape of the API, `src/api/openapi.json`):

```bash
npm run mock             # :8026
npm run dev:mock         # dev server proxied to the mock
# sign in: demo@mailr.test / demo-password-123
```

## Check and build

```bash
npm run typecheck        # tsc -b
npm run lint             # eslint, zero warnings allowed
npm test                 # vitest: pure helpers in src/lib
npm run build            # dist/ (static files; serve with SPA fallback to index.html)
```

The backend serves `dist/` in production. Any route that is not `/api/*` must fall back to
`index.html`. `sw.js` must be served from the root with no long cache.

## Structure

```
src/
  api/          client (fetch, CSRF, SSE parsing, uploads), types (contract), hooks (queries,
                optimistic actions), events (SSE + /changes catch-up)
  components/   Popover/Menu, Dialog, Toasts, TooltipLayer, bits (Avatar, LabelChip, …)
  features/
    auth/          sign-in page (local + OIDC)
    layout/        AppShell, TopBar (quick settings, account), Sidebar (nav + labels)
    mail/          MailPage (reading panes), MailList (tabs, Priority Inbox sections,
                   virtualised list), ConversationRow, ListToolbar, menus (label/move/snooze)
    conversation/  ConversationView, MessageCard, MessageBody (sandboxed iframe)
    compose/       ComposeDock (floating windows), ComposeForm, Editor (TipTap), RecipientField
    search/        SearchBar, AdvancedSearchForm, SearchChips
    rail/          side panels: Calendar, Tasks, Assistant (agent chat)
    settings/      tabs: General, Labels, Inbox, Accounts (+ wizard), Filters, Agents & API,
                   Calendar, Admin
    shortcuts/     Gmail keyboard shortcuts + help overlay
  hooks/        theme, media queries
  lib/          pure helpers (format, search, shortcuts, snooze, html, labels, views) + tests
  stores/       Zustand: UI state (selection, toasts, panels), compose windows
  styles/       tokens, base, components, layout, list, conversation, compose, settings, rail
mock/server.mjs mock API for development and UI testing
public/         PWA manifest, icons, service worker (app shell only; never caches /api)
```

## Notes

- **Mail HTML** is sanitised by the server and rendered in an iframe with `sandbox` (no
  scripts) and a CSP that blocks remote images until the user allows them. In dark mode,
  emails that set their own colours render on a light "paper" card.
- **Optimistic actions** update every cached list and detail and roll back on error. Every
  reversible action shows an Undo toast (`z` also undoes).
- **Live updates** use SSE `/api/v1/events` with debounced query invalidation, and catch up
  through `/changes` after a reconnect or when the tab becomes visible again.
- The typed API routes are in `src/api/openapi.json` and `src/api/schema.gen.ts`
  (generated by `tools/api-types`); the [API routes page](../site/docs/reference/api-routes.md) lists them all.
